# Skins migration plan — от хардкода к токенам и шкуркам

Статус: план этапа. Порядок исполнения — строго по фазам, каждая фаза — отдельный прогон тестов.

## Фаза 0. Заморозка (сейчас)

- Новые магические числа в `ui/` запрещены уже сейчас: нет числа в `tokens/layout.json` — сначала токен.
- `DESIGN` в `ui/gui.py` — единственный легальный источник до появления `app/skins.py`.

## Фаза 1. Токенизация без смены картинки (первой)

1. `app/skins.py`: `load_tokens()` читает `tokens/layout.json`, accessor `token("space.md")`. Только чтение, поведения не меняет.
2. `DESIGN` переключить на значения из токенов: `spacing 6→8` (`space.sm`), `margins (8,8,8,8)` уже `edge.safe`. Изменение 6→8 — единственный видимый сдвиг фазы; проверить скрин-ревью.
3. Точечные отступы по аудиту (13×`10px`, 5×`6px`, 10×`20px`, 1×`14px`, 2×`1px`): каждый маппим на ближайший токен шкалы, поштучно, с прогоном `check_polish` после каждой группы.
4. QSS `margin/padding` вне шкалы (`dialogs.py`, `styles.py`, `language_popup.py:7px`): переписать через токены, `width: 80%` в `dialogs.py:330` — на фиксированный `component.*` токен.

## Фаза 2. Проверки (ШАГ 6 спеки)

- Линтер `%` в edge-отступах + fit-чекер + dev-overlay. Красный чекер = блок коммита.

## Фаза 3. Шкурки

1. `skins/default/` — вынести текущие QSS/палитру/иконки как шкурку по контракту `docs/skins-architecture.md`.
2. `skins.set_active()` + QSettings `appearance/skin_id` + пункт меню.
3. Вторая шкурка (`dark-compact`) как доказательство контракта.

## Что менять первым

`app/skins.py` (ридер токенов) → `DESIGN` → точечные margins/spacing по списку аудита → QSS → чекеры → `skins/default`.

## Как не сломать UI

- Одна фаза — один прогон: `compileall` + `check_polish` + `check_features` + smoke `entry.py` + скрин с overlay.
- Числа меняем только на соседние по шкале (6→8, 10→8/12, 14→12/16, 20→16/24).
- `_sync_card_heights` и пропорции `3:2` не трогаем до Фазы 3.
- Откат фазы = revert одного коммита (фазы коммитятся отдельно).
