# Skins architecture — «шкурки» как модули

Статус: спека этапа. Код миграции — только после согласования контракта и токенов.

## 1. Определение

**Шкурка (skin)** — сменный модуль внешнего вида. Поставляет только презентацию:

- токены: цвета, радиусы, шрифтовые акценты, отступы (ссылками на `tokens/layout.json`, своих чисел не вводит);
- лейаут-правила: переопределение stretches/gaps в пределах сетки из `docs/layout-grid.md`;
- оверрайды компонентов: QSS-фрагменты на каждый виджет (`profile`, `auth`, `table`, `dialogs`, …);
- иконки: замены `assets/` в формате SVG, те же имена файлов.

Шкурка НЕ поставляет:

- бизнес-логику (`app/steam_api.py`, `app/grouping.py`, `app/cache.py`, воркеры, экспорт);
- данные и строки (все тексты — только через `app/i18n`, шкурка текстов не содержит);
- новые виджеты и поведение (сигналы/слоты не трогает);
- сетевые и файловые доступы, кроме чтения собственных ресурсов.

## 2. Контракт шкурки

Расположение: `skins/<skin_id>/` рядом с кодом. Обязательные файлы:

```
skins/<skin_id>/
  skin.json            # манифест (см. ниже)
  tokens.patch.json    # переопределения токенов (только существующие ключи)
  components/
    profile.qss
    auth.qss
    table.qss
    dialogs.qss
    chrome.qss         # меню, футер, тулбары
  icons/
    <имя>.svg          # опционально, имена совпадают с assets/
```

`skin.json`:

```json
{
  "id": "dark-compact",
  "version": "1.0.0",
  "base": "default",
  "components": ["profile", "auth", "table", "dialogs", "chrome"],
  "tokens": "tokens.patch.json"
}
```

Правила валидации (ядро отклоняет шкурку целиком при любом нарушении):

1. `id` — `[a-z0-9-]{1,32}`, совпадает с именем папки.
2. `tokens.patch.json` содержит только ключи из `tokens/layout.json`, значения — того же типа.
3. QSS-фрагменты: только селекторы из белого списка ядра (`QGroupBox#profile`, …); запрещены `QApplication`, глобальный `*`, `margin/padding` в `%` (см. ШАГ 6).
4. Иконки: только SVG, те же viewBox/имена, что в `assets/`.
5. Никаких `.py`, `.dll`, `.exe`, скриптов — только данные.

Способ подключения: ядро (`app/skins.py`, появится при миграции) сканирует `skins/*/skin.json` при старте, валидирует, строит итоговый словарь `токены базы + patch` и склеивает QSS `база + компоненты шкурки`. Виджеты читают значения только через accessor ядра (`skins.token("space.md")`), напрямую QSS-строки не собирают.

## 3. Выбор активной шкурки в рантайме

- Идемпотентно и без пересборки: ` skins.set_active("<id>") ` перечитывает манифест, переприменяет палитру + QSS + иконки, вызывает `retranslate_ui()`-подобный проход.
- Активная шкурка хранится в `QSettings` (`appearance/skin_id`), дефолт — `default`.
- Невалидная шкурка: молча остаётся предыдущая валидная + запись в лог. Падения UI из-за шкурки быть не должно.
- Переключение доступно из меню настроек и горячими клавишами; смена языка/темы `dark/light` остаётся ортогональной (палитра — часть шкурки, язык — нет).

## 4. Границы: где заканчивается шкурка

| Шкурка | Ядро |
|---|---|
| Значения токенов, QSS, SVG | Валидация, применение, фолбэк на `default` |
| Порядок/видимость в пределах сетки (gaps, stretches из шкалы) | Сама сетка: колонки, направляющие, edge-правила (`docs/layout-grid.md`) |
| Текст подсказок вида (тултипы — нет, это i18n) | Все строки через `tr()` |
| — | Расчёт размеров контента (`sizeHint`), `_sync_card_heights`, пагинация, сортировки |

Эвристика границы: если изменение требует правки `.py` вне `app/skins.py` и `ui/styles.py` — это уже не шкурка, а фича ядра.
